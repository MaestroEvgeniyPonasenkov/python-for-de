# Домашнее задание. Учёт банковских операций

Цель: спроектировать и реализовать объектную модель учёта банковских операций с опорой на материалы тем 1–5 (файлы, `datetime`, `pandas`, регулярные выражения, ООП).

Решение оформляется в объектно-ориентированном стиле. Конкретную структуру классов, имена методов и способ хранения данных выбирает автор. Поведение системы должно соответствовать правилам ниже, а демонстрация в ноутбуке — это подтверждать.

Сдача: ссылка на Google Colab или GitHub (если использовался Jupyter Notebook). По ссылке должен быть доступ для другого логина.

## Контекст

Небольшая модель учёта банковских счетов: расчётный и сберегательный. Система ведёт историю операций, валидирует входные данные, отличает успешные операции от отклонённых и даёт простую аналитику.

## Задание 1. Модель счёта и история

Реализовать модель банковского счёта, которая меняет баланс и ведёт детальную историю действий.

### Этап 1. Правила

- Счёт открывается с именем владельца и начальным балансом. Начальный баланс не может быть отрицательным, по умолчанию `0`.
- Номер счёта формируется автоматически в формате `ACC-XXXX`, где `XXXX` — порядковый номер. Счётчик начинается с `1000`. Номера уникальны.
- Поддерживаются пополнение и снятие.
- Сумма операции должна быть положительной. Некорректная сумма приводит к исключению.
- При успехе баланс обновляется, в историю добавляется запись со статусом успешной операции.
- Если средств недостаточно, баланс не меняется, но попытка фиксируется в истории со статусом неуспешной операции.
- Каждая запись истории — структурированные данные. Минимум полей:
  - тип операции (`deposit` / `withdraw`);
  - сумма;
  - дата и время (модуль `datetime`);
  - баланс после операции;
  - статус (`success` / `fail`).
- Можно узнать текущий баланс и получить историю операций в удобном для чтения виде.

### Этап 1. Демонстрация

В ноутбуке показать:

- создание счёта;
- несколько успешных пополнений и снятий;
- хотя бы одну неуспешную попытку снятия;
- вывод баланса и истории.

### Этап 2. График

По истории операций построить линейный график изменения баланса во времени:

- ось X — время операции;
- ось Y — баланс после операции;
- у графика есть заголовок и подписи осей;
- данные для графика берутся из истории через `pandas`.

## Задание 2. Типы счетов и аналитика

Расчётный и сберегательный счета отражают общее поведение учёта операций и отличаются правилами.

### Правила

- **Расчётный счёт** — базовые пополнение и снятие без дополнительных ограничений на долю снимаемой суммы.
- **Сберегательный счёт:**
  - умеет начислять проценты на текущий остаток (ставку задаёт вызывающий код, например 7%);
  - нельзя снять больше 50% текущего баланса;
  - нарушающая правило попытка не меняет баланс и фиксируется в истории как неуспешная.
- У каждого типа счёта есть различимый тип: по объекту или данным понятно, расчётный это счёт или сберегательный.
- Валидация имени владельца: формат «Имя Фамилия», слова с заглавной буквы, кириллица или латиница. Иначе — исключение. Проверка через регулярные выражения.
- Аналитика по истории: последние N крупных успешных операций. Порог «крупности» и N задаёт вызывающий код.

### Демонстрация

В ноутбуке показать:

- создание расчётного и сберегательного счёта;
- начисление процентов на сберегательном;
- отклонение снятия сверх 50% на сберегательном;
- выборку последних крупных операций;
- реакцию на некорректное имя владельца и/или некорректную сумму.

### Дополнительно. Перевод между счетами

Необязательный пункт. Без него сложно претендовать на верхнюю часть шкалы.

- При успехе сумма списывается у отправителя и зачисляется получателю.
- Если списание у отправителя невозможно (недостаточно средств или сработало ограничение сберегательного счёта), баланс получателя не меняется.
- В историях обоих счетов перевод различим: общий идентификатор перевода, связанные записи или иной явный признак.

## Задание 3. Загрузка «грязных» данных

Файлы в каталоге задания:

- `transactions_dirty.csv`
- `transactions_dirty.json`

Файл общий для нескольких счетов. В конкретный счёт загружаются только его операции (фильтрация по номеру счёта и/или типу — по данным файла).

Колонки / поля записей: `account_number`, `account_type` (`checking` / `savings`), `date`, `operation`, `amount`, `balance_after`, `status`.

### Правила

- Реализовать загрузку истории из CSV и/или из JSON.
- Перед записью в историю отбрасывать невалидные строки: опечатки в типе операции, пустые или отрицательные суммы, некорректные даты, некорректный статус и т.п.
- Для сберегательного счёта допустимы типы `deposit`, `withdraw`, `interest`. Для расчётного — только `deposit` и `withdraw`. Операции, недопустимые для типа счёта, невалидны.
- После успешной загрузки валидных операций баланс счёта соответствует последовательности принятых операций.

### Демонстрация

Загрузить данные хотя бы из одного формата в расчётный и в сберегательный счёт. Показать обновлённый баланс и фрагмент истории.

### Дополнительно. Отчёт об отбраковке

Необязательный пункт. Без него сложно претендовать на верхнюю часть шкалы.

Помимо отбрасывания мусора сформировать явный результат очистки:

- сколько строк принято;
- сколько отклонено;
- почему отклонена каждая строка или группа строк (битая дата, пустая сумма, опечатка в типе вроде `diposit`, `interest` на расчётном счёте, неверный статус и т.д.).

Формат отчёта на выбор (список, датафрейм, печать сводки). Отчёт должен быть показан в ноутбуке и по нему должно быть понятно, что произошло с данными.
